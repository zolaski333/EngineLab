## Scope and status definitions

The baseline is `out/audit2/inventory.json`: all files returned by `git ls-files` at continuation start, with byte hashes and line counts. First-party source, tests, tools, project data and documentation are included. Generated builds, fetched third-party implementation trees, local measurement exports (`essai-sortie/`, `sources-gratuites/`) and the audit artifacts themselves are outside that product-file denominator; their relevant dependency, packaging and evidence contracts are inspected separately. No ignored build tree is silently labelled reviewed.

`Full text review` means the assigned reviewer reports reading the entire file and tracing relevant contracts. Binary resources receive integrity/metadata/local-attribution checks, not a fictitious source review. The per-file hash must still match the reviewed bytes; changed files revert to pending. Source review and executable validation are recorded separately. A file without a finding is not certified correct.
